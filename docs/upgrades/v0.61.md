# v0.61 upgrade

Upgrade name `v0.61`. It moves nyxd from wasmd v0.60.0 to wasmd v0.61.16.

| | v0.60.1 (current mainnet) | v0.61 |
|---|---|---|
| wasmd | v0.60.0 | v0.61.16 |
| wasmvm | v2.2.1 | v3.0.9 |
| cosmos-sdk | v0.53.3 | v0.53.6 |
| CometBFT | v0.38.18 | v0.38.21 |
| ibc-go | v10.0.0 | v10.5.0 |
| hyperlane-cosmos | v1.0.0 | v1.1.0 |
| iavl | v1.2.8 | v1.2.8 |
| Go (release builds) | 1.23.11 | 1.26.9 |

The upgrade is consensus breaking and goes through governance. No store is added or
removed, and no module changes its consensus version. Besides `RunMigrations`, the
handler pins four contracts and hands pinning to the Nym admin multisig (see below).

It includes the CosmWasm fix for the critical fund-loss issue disclosed on 2026-09-24
(nil `Ok` responses from the VM, and the vesting burn amount). v0.60.1 does not have it.

## Validators

1. v0.61 release binaries are built with Go 1.26.9; use that version when building from
   source. The binary links wasmvm v3, so ship `libwasmvm.x86_64.so` v3.0.9 next to it.
   The v2 library from v0.60 will not load.
2. Stage the release in its own directory before the upgrade height. The v3 library has
   the same file name as the v2 one, so do not copy it over the v2 library your running
   node loads (often `/lib/x86_64-linux-gnu/libwasmvm.x86_64.so`): v0.60 would fail on
   its next restart. Point the new binary at its own copy instead, for example with a
   systemd drop-in:

   ```
   [Service]
   Environment=LD_LIBRARY_PATH=/opt/nyxd/v0.61.16
   ExecStart=
   ExecStart=/opt/nyxd/v0.61.16/nyxd start --home /home/nym/.nyxd
   ```

   `LD_LIBRARY_PATH=/opt/nyxd/v0.61.16 ldd /opt/nyxd/v0.61.16/nyxd | grep wasmvm` must
   show the staged library.
3. When the node halts with `UPGRADE "v0.61" NEEDED`, stop it, switch to the new binary
   (for example `systemctl daemon-reload` after adding the drop-in) and start it.
   wasmvm v3 does not reuse the v2 module cache, so expect contracts to be compiled
   again on first use after the switch.
4. Do not start the v0.61 binary before the upgrade height. The upgrade module should
   refuse with `upgrade handler is missing for v0.60 upgrade plan` (x/upgrade
   `abci.go`, since mainnet's last applied plan is v0.60). This was read from the
   source, not observed on a mainnet copy.

The upgrade was rehearsed on sandbox (proposal 36, applied at height 19220908 with
v0.61.16-rc.0): the node halted at the upgrade height, the new binary applied the
upgrade, stored codes, contract state and hyperlane mailboxes were unchanged, and
existing contracts ran under wasmvm v3. It was also applied to a copy of mainnet state at
height 26064002.

## Contract pinning

At the upgrade height the handler pins the code of the mixnet, directory, ecash and
geolocation contracts, looked up by contract address. A pinned contract stays compiled in
memory on every node, and each transaction that calls it costs 58,000 gas less. On a
mainnet fork that took 27% off a directory submission, 42% off a mixnet delegation and
33% off a single ecash deposit. Repeat calls to the same contract in one transaction were
already discounted, so large batches gain little. At current volumes the four contracts
save about 192M gas a day.

Each node holds about 45 MiB more in wasmvm's pinned cache (mixnet 22.0, ecash 9.3,
geolocation 7.0, directory 6.5), measured as about 77 MiB more resident memory. The
pinned set is reloaded from chain state on every start.

The handler also stores two authz grants from the gov module account to the Nym admin
multisig `n1txe3x04c3wjejfn4my4ef3n4t4dfhfajcwqg9t`: one for `MsgPinCodes` and one for
`MsgUnpinCodes`. Governance stays the wasm authority. The multisig can change the pinned
set without a proposal, through `nyxd tx authz exec` with a message whose `authority` is
the gov address `n10d07y265gmmuvt4z0w9aw880jnsr700jgxy8fk`, and it can do nothing else
with the grants. A governance proposal with `MsgRevoke` removes them. Chains that do not
hold these contracts (sandbox, local devnets) get neither the pins nor the grants.

## State sync

State sync was broken from v0.54.0 to v0.60.1 (nymtech/nyxd#81). The app constructor
wrote default mint state on startup. On a fresh node that left uncommitted data in the
`mint` IAVL tree, and the snapshot import refused the store with
`multistore restore: import failed: tree must be empty`. The stores restored before
`mint` stayed on disk, so every retry in the same directory failed with
`found database at version N, must be 0`. IAVL itself was fine. The app wrote to the
tree before the import started.

v0.61 removes that write, and `TestStateSyncIntoFreshNode` covers it in CI.

If a node ever logged `found database at version N`, its `data/` holds a half-restored
state. Reset it before trying again, even with a fixed binary:

```
nyxd comet unsafe-reset-all --home <home> --keep-addr-book
```

Mainnet peers serve snapshots every 2000 blocks, so `statesync.enable = true` with a
recent trust height and hash is enough.

State sync and block sync need an x86-64 machine. Mainnet contract code 54 does not
compile on arm64 (Wasmer reports `ImpossibleRelocation`), with wasmvm v2.2.1 and v3.0.9
alike, so an arm64 node fails at the wasm snapshot step or when it reaches that code.

## Pruning

The hang in nymtech/nyxd#80 came from v0.54 pruning inside `Commit`. The first prune
that reached the versions written before the SDK 0.50 upgrade ran a one-time cleanup of
the old IAVL format. It used full CPU and logged nothing until it finished. On a 292 MB
test tree that cleanup blocks a commit for 8 to 10 seconds. On mainnet state it took far
longer. iavl v1.2.4 then failed later prunes with `version does not exist`.

Since v0.60 the store prunes in a background goroutine (async pruning is the default in
cosmossdk.io/store v1.1.2), and iavl v1.2.8 skips missing versions. Both fixes are in
v0.61. Recommended settings:

- `pruning = "custom"`, `pruning-keep-recent = "100"` or more, `pruning-interval = "10"`.
- Leave `iavl-sync-pruning` off. Turning it on brings the blocking cleanup back.
- Set `snapshot-interval = 0` unless the node serves state sync. The pruner never prunes
  past the oldest snapshot height it tracks, and prunes nothing before the first
  snapshot. On a snapshot server, pick the interval once and keep it.
- Stop nodes with SIGTERM and give them time. `Close()` waits for background pruning.

The capability, feeibc, params and crisis stores left the app in v0.60 without being
deleted. Their last versions stay in `application.db` and are never pruned. State sync
into a new data dir is the only way to drop them.

## Forking mainnet for testing

`scripts/testnetify.sh` turns a copy of a stopped node's home into a single-validator
testnet. It runs `nyxd in-place-testnet`, which keeps all state except the validator set.

```
scripts/testnetify.sh -s /path/to/stopped-node-home -o ./fork -u v0.61 -f n1yourkey...
```

`-u v0.61` runs the upgrade handler on the first block of the fork, which is how to
rehearse this upgrade on real mainnet state. The fork's validator is a fresh key with a
regular self-delegation. Every old validator is jailed and unbonded, and their
delegations and rewards stay valid. The fork shortens the gov voting period to 60s, so a
proposal passes on the new validator's vote alone.

The old `scripts/testnetify.py` edits a genesis export instead. It replaces two
hard-coded mainnet validators and writes `capability` and `feeibc` genesis sections that
no longer exist, so it does not work on v0.60 or later.
